## Patterns & Surprises

### Took longer than expected

- The mini-context-graph SKILL.md references Python modules
  (`scripts/contextgraph`, `scripts/tools`) that don't exist in the
  godmode plugin cache. Had to build all backing code from scratch based
  on the spec -- the skill is a pattern doc, not a working tool.

### Went smoothly

- All Python modules worked on first run after writing. The smoke test
  passed immediately with no bugs.
- Entity/relation extraction from source code was straightforward --
  the codebase has clean trait boundaries that map directly to graph
  nodes and edges.
- Backfilling 67 entity pages from graph nodes was a single automated
  pass with no manual intervention.

### Discovered mid-session

- Initial ingestion missed 9 `depends_on` edges from sub-crates to
  `langchainx-core`. The generic query for "Chain" also matched
  "langchainx" due to substring matching in the search -- the retrieval
  engine's keyword search is naive and could benefit from exact-match
  boosting or slug-based lookup.
- The `query()` method's first-match heuristic means the "best" node
  returned depends on insertion order, not relevance. A future
  improvement would be TF-IDF or edit-distance scoring.

### Next session speedups

- Add a `graph_store.find_by_relation(target, relation)` helper to
  avoid filtering edges manually in every query.
- Consider adding the context graph scripts to `.gitignore` exclusion
  so they persist across branches but don't pollute diffs.
- The wiki lint shows 9 orphan pages (leaf entities not linked from
  summaries) -- a quick pass linking them from the relevant summary
  page would close those.
